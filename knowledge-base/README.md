# Knowledge library

There are two verified source-game lessons within the pure-logic test boundary: [staged rules and duplicate intents](rule-stack-kernel.md), and [hidden-choice snapshots and acknowledgement recovery](dont-match-me-private-acks.md). Engine, device and gameplay feel remain unverified. Imported research is kept separately from tested lessons. `_template.md` is a blank authoring template, not a knowledge entry.

Add entries only for important, reusable findings such as mobile UI, networking, saving, or exploit prevention. Load only entries relevant to the current work.

Each entry must:

- Use a descriptive filename and start with `VERIFIED` or `UNVERIFIED`.
- Link its source game and the relevant test, playtest correction, or observation.
- State a concrete rule, its scope, and the evidence supporting it.
- Distinguish an observed result from an assumption. Never invent a source game or verification.

`VERIFIED` means the stated rule has direct, recorded evidence within its declared scope. `UNVERIFIED` means it is a hypothesis or proposed rule awaiting that evidence. Passing a narrow test does not verify unrelated behavior.

Every correction from Snow's playtesting becomes a rule. Link back to the correction, explain its scope, and tag it honestly. Update a contradicted rule with the new evidence rather than leaving competing instructions without explanation.
